# Search for New Houses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `casa-certa run trip.yaml [--search] [--analyse]` finds houses on Airbnb for the yaml's `search.locations`, screens them cheaply on the free listing data, analyses the survivors with the existing pipeline and cache, and logs what each house cost.

**Architecture:** A `SearchSource` adapter (Apify actor behind a Protocol, chosen by `SEARCH_SOURCES`) feeds a stored "last search". The pipeline takes a list of rooms (yaml urls never screened, searched hits screened) and gains a screen stage between the free page fetch and the paid steps. A `CostTracker` collects Apify and DeepSeek spend per house through context managers and sinks. The CLI resolves `--search`/`--analyse`/prompts into those stages.

**Tech Stack:** Python 3.11+, asyncio, SQLAlchemy 2 async + Alembic, Pydantic / pydantic-settings, Pydantic AI (DeepSeek), `apify-client`, pytest + pytest-asyncio, uv, ruff, mypy strict.

**Spec:** `docs/superpowers/specs/2026-11-01-search-design.md` (also read `docs/superpowers/specs/2026-10-31-cheaper-sources-design.md` for the adapter pattern).

## Global Constraints

- All code-related text is English; Portuguese only for user-facing output and Airbnb data. Commits are Conventional Commits; never `--no-verify`.
- `ruff` 120 cols, `mypy --strict` on `casa_certa` (tests may omit annotations). Run `make check` before every commit.
- Async everywhere. No JSON columns: typed columns and child tables only. Money is integer cents in the DB; cost *logging* uses float USD.
- Dependencies are passed in (constructor arguments), not imported globally. Prefer context managers, dataclasses, `Protocol`.
- Tests use fakes (`tests/fakes.py: FakeRunner`, Pydantic AI `TestModel`/`FunctionModel`); live tests are `@pytest.mark.live` and skipped by default. Never call Airbnb's private API.
- Personal data stays out of the repo: new fixtures are anonymized (no host/reviewer names, photos, profile ids, exact coordinates: round to 2 decimals). `trip.yaml` is gitignored; do not commit it, `.db`, `.xlsx` or `.env`.
- Cache rule: never re-fetch or re-analyse stored data unless `--refresh` (or the input hash changed). Hits already stored are skipped before the plan is shown.
- Search request values come from the spec: capacity at least `max_people` paying guests; `infants` passed as in price quotes; `search.max_results` default 40 per location; optional `max_price_per_night` (BRL) and `min_rating`.
- The screen drops a house **only if at least one `must_have` is `fails`**; `unclear` passes. Never screens houses listed in the yaml `urls`. Skipped when there are no must-haves.
- `--search --analyse` asks nothing, cost confirmation included. No flags: ask "Search?" (only if the yaml has `search:`) then "Analyse everything found?". Without a `search:` block, no flags behaves as `run` does today (cost confirmation only).
- The user's `trip.yaml` is edited only by adding the new `search:` block; no other line changes.

## Review Focus

Inputs the spec implies but the main flow does not exercise (each has its test in the owning task):

1. The same house returned by two locations (Task 4 test, Task 7 test): stored and analysed once.
2. One location failing or returning zero hits (Task 7): the others still run, a message is printed, and `--analyse` with nothing to analyse says to run `--search` first (Task 9).
3. Hit URLs with other domains, query strings (`?check_in=...`) or `/rooms/plus/` forms (Task 3): all normalise to one room id.
4. The screening model returns a verdict for an aspect that was not asked or omits one (Task 5): retried like the analyst, not accepted.
5. Prompt answered on a closed stdin (EOF) or with empty input (Task 9): treated as "no", never a traceback or an accidental spend.

### Task 9: CLI — flags, modes, prompts, dry-run

**Files:**
- Modify: `casa_certa/cli.py`, `tests/test_cli.py`

**Interfaces:**
- Consumes: everything above.
- Produces: `run` gains `--search` and `--analyse` (store_true). Pure, testable pieces: `@dataclass class RunMode`: `search: bool`, `analyse_after_search: bool | None`, `assume_yes: bool`; `async def resolve_mode(args, trip, ask: Callable[[str], Awaitable[bool]]) -> RunMode`. Rules: both flags → search, analyse, `assume_yes=True` (no prompts, no cost confirmation); `--search` only → search, no analysis; `--analyse` only → analyse, no search; neither → if `trip.search` ask "Search?" then (after the search ran) ask "Analyse everything found? (estimated cost shown)"; if no `trip.search`, behave as today. `--search` when the yaml has no `search:` block → `ConfigError("--search needs a search: block in the trip file")` (exit 2). `--analyse` with no `urls` and no stored search hits → `ConfigError` saying to run `--search` first. `ask` reads stdin via `asyncio.to_thread(input, ...)`; `EOFError` or empty input counts as no.
